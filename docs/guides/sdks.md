# Generate SDKs and a CLI

This page gets you a typed client for your API in Go and TypeScript, and a command-line program for it, generated by [Fern](https://buildwithfern.com) from the specs your contract writes. Read it when another developer, or another service of yours, has to call the API.

You need Docker running: Fern runs its generators in containers. Everything here was run on 2026-10-01 in a project made by `dev new -name billing-api`, so the names below are that project's.

## Generate one

```sh
mise run api-go:spec                 # the specs, from the contract (do this after every contract change)
mise run sdk:gen api-go typescript   # TypeScript source      -> sdk/out/api-go/typescript
mise run sdk:gen api-go go           # a Go module            -> sdk/out/api-go/go
mise run sdk:gen api-go typescript-dist   # TypeScript compiled to .js and .d.ts -> sdk/out/api-go/typescript-dist
mise run sdk:gen api-go cli          # a Rust CLI, as source  -> sdk/out/api-go/cli
mise run sdk:list                    # the groups there are: "api-go: go typescript cli typescript-dist"
```

Each took 10 to 25 seconds here, with the generator images already downloaded. A generation replaces the folder.

- **`sdk/out/` is not committed** (it is in `.gitignore`). An SDK is a build output: generate it again from the committed specs.
- **`typescript` or `typescript-dist`:** the first is `.ts` source, to copy into a TypeScript project or to read. The second is what Node or a Worker imports without a build step, and what the test programs in `test/` use.
- **`mise run sdk:ready api-go`** generates the three groups the tests use (`typescript-dist`, `go`, `cli`) and builds the CLI, each only if its folder is missing. After a contract change, run `mise run sdk:clean` first, or generate the group again yourself: `sdk:ready` does not notice a stale SDK.

## What Fern reads: the Fern folder

```
sdk/fern/apis/api-go/
├── openapi.json      written by mise run api-go:spec (never edit)
├── asyncapi.json     the same, for the WebSocket channel
└── generators.yml    yours: one group per SDK, with its options
```

A group in `sdk/fern/apis/api-go/generators.yml` names a Fern generator, its pinned version, where the output goes, and its options. `sdk/fern/fern.config.json` holds the Fern organization name, and `sdk/package.json` pins Fern itself.

What an SDK contains comes from the contract, not from this folder: the method names (`notes.list`), auto-paging and the SSE stream are declared on each operation in `api-go/api/contract.go`.

## Check that an SDK works

```sh
mise run sdk:check sdk/out/api-go/go           # go build, go vet, and Fern's generated tests against a WireMock container
mise run sdk:check sdk/out/api-go/typescript   # a typecheck against standard fetch, without Node's types
mise run sdk:check-spec api-go                 # Fern's own validation of the specs and generators.yml
```

Output here:

```
build ok
vet ok
tests ok
typecheck ok (sdk/out/api-go/typescript/index.ts)
```

`sdk:check` proves the SDK compiles and passes Fern's own tests against a mock. It does not call your server. The tests that do are in [Test locally and on Cloudflare](testing.md).

## Build the CLI

```sh
mise run sdk:cli:build sdk/out/api-go/cli     # HEAVY the first time: compiles every Rust dependency
sdk/out/api-go/cli/target/release/billing-api --base-url http://localhost:5174 notes list --page-all
```

The build took 43 seconds here (an Apple M-series Mac). It needs Rust, which `mise install` provides at the version in `rust-toolchain.toml`. With `-linux` before the folder it builds a Linux binary inside Docker instead, into `target-linux/`.

Run against `mise run api-go:run`:

```
$ billing-api --base-url http://localhost:5174 meta hello
{
  "message": "Hello from billing-api (go run)"
}
$ billing-api --base-url http://localhost:5174 notes create --body first
{
  "body": "first",
  "created_at": "2026-10-01 09:36:22",
  "id": 1
}
```

Without `--base-url` it calls the server named in the specs ([Deploy to Cloudflare](deploy.md#the-workers-url)). `--help` lists the rest: output formats (`--format json|table|yaml|csv|raw|jsonl|http`), `--query`, `--dry-run`, `--schema`.

Limits of the generated CLI:

- **`notes watch` prints nothing until the stream ends** in the `json` and `jsonl` formats. `--format raw` prints as events arrive, as raw SSE lines ([upstream issues](../upstream.md)).
- **No command for the WebSocket channel.**
- **One binary per build:** for the machine you build on, or Linux with `-linux`.

## Use the SDK

Both snippets were run against `mise run api-go:run`. Leave out the base URL and the client calls the server named in the specs.

TypeScript, importing the compiled SDK from the project's root:

```ts
import { BillingApiClient } from "./sdk/out/api-go/typescript-dist/esm/index.mjs";

const client = new BillingApiClient({ baseUrl: "http://localhost:5174" });

const note = await client.notes.create({ body: "first" });

// list: the SDK fetches the next page when the loop needs it
for await (const n of await client.notes.list({ limit: 50 })) console.log(n.id, n.body);

// watch: notes after a position, as they are created, until the stream ends
for await (const n of await client.notes.watch({ after: String(note.id - 1), seconds: 5 })) console.log("new", n.body);
```

Go:

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"io"
	"log"

	billingapi "example.com/billingapi"
	"example.com/billingapi/client"
	"example.com/billingapi/option"
)

func main() {
	ctx := context.Background()
	c := client.NewClient(option.WithBaseURL("http://localhost:5174"))

	note, err := c.Notes.Create(ctx, &billingapi.CreateInputBody{Body: "first"})
	if err != nil {
		log.Fatal(err)
	}

	// list: the iterator fetches the next page when it needs it
	page, err := c.Notes.List(ctx, &billingapi.ListNotesRequest{Limit: billingapi.Int(50)})
	if err != nil {
		log.Fatal(err)
	}
	for it := page.Iterator(); it.Next(ctx); {
		fmt.Println(it.Current().ID, it.Current().Body)
	}

	// watch: notes after a position, as they are created, until the stream ends
	after := fmt.Sprint(note.ID - 1)
	stream, err := c.Notes.Watch(ctx, &billingapi.WatchNotesRequest{After: &after, Seconds: billingapi.Int(5)})
	if err != nil {
		log.Fatal(err)
	}
	defer stream.Close()
	for {
		n, err := stream.Recv()
		if errors.Is(err, io.EOF) {
			return
		}
		if err != nil {
			log.Fatal(err)
		}
		fmt.Println("new", n.Body)
	}
}
```

The Go SDK's module path is not a real repository, so a program that uses it points at the folder. In that program's `go.mod`:

```
require example.com/billingapi v0.0.0

replace example.com/billingapi => ../sdk/out/api-go/go
```

- **A stream ends on purpose** after `seconds`. A client that wants to keep following calls `watch` again with `after` set to the last note id it received. The loop for each client is in [What a client does](../realtime.md#what-a-client-does).
- **The WebSocket** is `client.liveNotes.connect({ after })` in the TypeScript SDK (on Node it needs the `ws` package). The Go SDK has the message types only, no WebSocket client.
- **Each generated SDK has its own `README.md` and `reference.md`,** listing every method.

## Change the names

All of them are in `sdk/fern/apis/api-go/generators.yml`. `dev new -name billing-api` set them from the project's name:

| Setting | Group | What it names | In a `billing-api` project |
|---|---|---|---|
| `config.module.path` | `go` | The Go module path of the SDK | `example.com/billingapi` |
| `config.packageName` | `go` | The Go package name | `billingapi` |
| `config.namespaceExport` | `typescript`, `typescript-dist` | The TypeScript client class, with `Client` added | `BillingApi` gives `BillingApiClient` |
| `config.binaryName` | `cli` | The CLI's binary | `billing-api` |

Set `module.path` to the repository the Go SDK will live in before you hand it to anyone: `example.com/...` cannot be fetched with `go get`.

Then generate again. The test programs use these names, so change them there too: `BillingApiClient` in `test/sdk-live-test.mjs` and `test/soak.mjs`, the binary's name in `test/soak.mjs`, and the module path in `test/soak-go/main.go`, `test/soak-go/go.mod` and `test/soak.mjs`.

Method names (`client.notes.list`) are not here. They come from the contract: `x-fern-sdk-group-name` and `x-fern-sdk-method-name` on each operation in `api-go/api/contract.go`.

## Add a language

Add a group to `sdk/fern/apis/api-go/generators.yml`, under `groups:`. For Python:

```yaml
  python:
    generators:
      - name: fernapi/fern-python-sdk
        version: 5.34.0
        output:
          location: local-file-system
          path: ../../../out/api-go/python
```

```sh
mise run sdk:gen api-go python       # -> sdk/out/api-go/python
```

That ran here and produced the client. It was not used against a server, and `mise run sdk:check` knows only Go and TypeScript SDKs. Fern's other generators (Java, C#, Ruby and more) take the same form: the generator's name, a pinned version, and the options listed in Fern's documentation for that generator. None of those was tried.

## Hand the SDKs to others

What exists is the release archive. A version tag on GitHub attaches these to the tag's GitHub Release ([CI and releases on GitHub](ci-releases.md#what-a-release-contains)):

| File | What is in it |
|---|---|
| `api-go-sdk-go.tar.gz` | The Go SDK's source |
| `api-go-sdk-typescript.tar.gz` | The TypeScript SDK's source |
| `api-go-specs.tar.gz` | `openapi.json` and `asyncapi.json` |
| `api-go-cli-linux-amd64` | The CLI, for Linux on amd64 |

To build the first three on your machine, without publishing anything:

```sh
mise run sdk:dist     # generates, checks and archives into dist/
```

Not set up:

- **Packages.** Nothing publishes the TypeScript SDK to npm or the Go SDK to a repository of its own. Fern can do both (an `output:` with `location: npm`, or a `github:` block, in place of `location: local-file-system`), and that has not been configured or tried here. Until it is, a user of the Go SDK unpacks the archive and uses a `replace` line as above, and a user of the TypeScript SDK copies the source into their project.
- **The CLI for macOS and Windows.** Build it on the machine that needs it.
- **Fern's licence.** Fern's documentation describes local generation and the CLI generator as needing a `FERN_TOKEN`. Everything on this page ran without one; `mise run doctor` prints a warning about it.
