# SDKs and releasing them

How to get typed clients and a command-line program for your API, generated by [Fern](https://buildwithfern.com) from the specs your contract writes, and how to hand them to other developers. You need Docker running: Fern generates in containers.

## Generate one

```sh
mise run spec                       # the specs, from the contract: after every contract change
mise run sdk:list                   # the groups: go typescript typescript-dist cli
mise run sdk:gen typescript         # TypeScript sources (.ts)               -> sdk/out/typescript
mise run sdk:gen typescript-dist    # TypeScript compiled (.js and .d.ts)   -> sdk/out/typescript-dist
mise run sdk:gen go                 # a Go module                           -> sdk/out/go
mise run sdk:gen cli                # a Rust CLI, as source                 -> sdk/out/cli
```

- **`sdk/out/` is not committed.** The one committed SDK is the Go one in `sdk/go/` ([below](#give-the-go-sdk-to-another-repo)).
- **`typescript-dist`** is what Node or a Worker imports without a build step, and what the tests use.
- **`mise run sdk:ready`** generates what the tests use, if missing. It does not notice a stale SDK: after a contract change run `mise run sdk:clean` first.
- **A group** in `fern/generators.yml` is one SDK: the generator, its pinned version, the output path, its options. Method names, auto-paging and streaming come from the contract instead ([the names](replace-the-example.md#the-names-in-the-sdks)).

## Check and use it

```sh
mise run sdk:check go            # go build, go vet, and Fern's generated tests against a WireMock container
mise run sdk:check typescript    # a typecheck
mise run sdk:check-spec          # Fern's own validation of the specs and generators.yml
```

That proves the SDK compiles and passes Fern's tests against a mock. The tests that call your server: [Test and CI](testing.md).

```ts
import { NotesClient } from "./sdk/out/typescript-dist/esm/index.mjs";

const client = new NotesClient({ baseUrl: "http://localhost:5174" });
const note = await client.notes.create({ body: "first" });
for await (const n of await client.notes.list({ limit: 50 })) console.log(n.id, n.body);   // fetches the next page itself
```

- **Without a base URL** the client calls the server the specs name: `API_URL`.
- **Go:** `client.NewClient(option.WithBaseURL(...))`, then `c.Notes.List(ctx, ...)`. `test/soak-go/main.go` is a complete program.
- **Streams:** [the client rule](streaming.md#the-client-rule). The WebSocket is `client.liveNotes.connect({ after })` in TypeScript (on Node it needs the `ws` package); the Go SDK has the message types only.
- **Each SDK has its own `README.md` and `reference.md`.**

The snippet makes the calls `test/sdk-live-test.mjs` makes. As written, it was not run.

## The CLI

```sh
mise run sdk:cli:build     # HEAVY the first time: compiles every Rust dependency. -linux builds for Linux in Docker
sdk/out/cli/target/release/notes --base-url http://localhost:5174 notes list --page-all
```

- **Flags:** `--format json|table|yaml|csv|jsonl|raw|http`, `--query` (JMESPath), `--dry-run`, `--base-url`, `--debug`, `--schema`.
- **A stream prints in `json` and `jsonl` only when it ends.** `--format raw` prints as events arrive ([fern-api/fern#17939](../upstream.md)).
- **No command for the WebSocket channel.** One binary per build.

## Add a language

Add a group to `fern/generators.yml`, under `groups:`, then `mise run sdk:gen python`.

```yaml
  python:
    generators:
      - name: fernapi/fern-python-sdk
        version: 5.34.0
        output:
          location: local-file-system
          path: ../sdk/out/python
```

- **A release then ships it** with no other change: every group but `cli` and those ending in `-dist` is archived.
- **`mise run sdk:check` builds and tests Go and TypeScript only.**
- **What was tried:** the Python client was generated on 2026-10-01 and not used against a server. Fern's other generators take the same form; none was tried.

## Give the Go SDK to another repo

Go fetches a module from a git repository, and `sdk/out/` is not in yours. One task copies the Go SDK into a committed folder, `sdk/go/`: a module of its own, `<your module>/sdk/go`.

```sh
mise run sdk:publish    # generates the Go SDK fresh, checks it, copies its sources into sdk/go
git add sdk/go          # commit it with the contract change it belongs to
```

In the other repo: `go get <your module>/sdk/go@main` straight away, `@latest` once a release has tagged it.

- **`mise run check` fails** when the specs changed since `sdk/go/` was made (`sdk:publish:fresh`: a hash, no Docker). The `sdk-check` workflow generates again and fails if the folder differs (`sdk:publish:check`).
- **Never edit `sdk/go/`.** Its README starts with a "Generated code" banner.
- **A private repo:** the machine that runs `go get` needs git access and `GOPRIVATE`.
- **Not handled:** major version 2 and later, where Go wants the module path to end in `/v2`. The TypeScript SDK has no committed copy and no package.

## Release

A release is a version tag. Push `vX.Y.Z` and the `release` workflow runs these; on a pull request it is a dry run.

| Task | What it makes |
|---|---|
| `mise run sdk:dist` | `dist/<project>-sdk-<group>.tar.gz` per SDK group and `dist/<project>-specs.tar.gz`, generated fresh and checked |
| `mise run sdk:dist:cli` | `dist/<project>-cli-<os>-<arch>`: Linux on amd64 in the workflow |
| `mise run release` | Attaches every file in `dist/` to the tag's GitHub Release |
| `mise run release:tags` | Tags `sdk/go/vX.Y.Z` on the tag's commit, so `@latest` works |

Not set up:

- **Packages.** Nothing publishes to npm or to a repository per SDK. Fern can; not tried here.
- **The CLI for macOS and Windows.** Build it on the machine that needs it.
- **Fern's licence.** Fern's documentation describes local generation and the CLI generator as needing a `FERN_TOKEN`. Everything here ran without one.
