# SDKs and releasing them

How to get typed clients and a command-line program for your API, generated by [Fern](https://buildwithfern.com) from the specs your contract writes, and how to hand them to other developers. You need Docker running: Fern generates in containers.

## Generate one

```sh
mise run spec                       # the specs, from the contract: after every contract change
mise run sdk:list                   # the groups: go typescript typescript-dist cli
mise run sdk:gen typescript         # TypeScript sources (.ts)                 -> sdk/out/typescript
mise run sdk:gen typescript-dist    # TypeScript compiled (.js and .d.ts)     -> sdk/out/typescript-dist
mise run sdk:gen go                 # a Go module                             -> sdk/out/go
mise run sdk:gen cli                # a Rust CLI, as source                   -> sdk/out/cli
```

- **`sdk/out/` is not committed.** An SDK is a build output of the committed specs. The one committed copy is the Go SDK in `sdk/go/` ([below](#give-the-go-sdk-to-another-repo)).
- **`typescript-dist`** is what Node or a Worker imports without a build step, and what the tests in `test/` use.
- **`mise run sdk:ready`** generates the groups the tests use and builds the CLI, each only if missing. It does not notice a stale SDK: after a contract change run `mise run sdk:clean` first.

## Fern's folder

| File in `fern/` | What it is | Who writes it |
|---|---|---|
| `openapi.json`, `asyncapi.json` | The specs | `mise run spec`. Never edit |
| `generators.yml` | One group per SDK: the generator, its pinned version, the output path, its options | You |
| `fern.config.json` | Fern's organisation name | `charter new` |
| `docs.yml` | The API's reference site (`mise run sdk:docs` previews it on port 3030) | You |

Method names, auto-paging and streaming come from the contract, not from this folder ([Change the contract](contract.md)). The client's own names are here ([the names in the SDKs](replace-the-example.md#the-names-in-the-sdks)).

## Check that an SDK works

```sh
mise run sdk:check go            # go build, go vet, and Fern's generated tests against a WireMock container
mise run sdk:check typescript    # a typecheck
mise run sdk:check-spec          # Fern's own validation of the specs and generators.yml
```

This proves the SDK compiles and passes Fern's tests against a mock. The tests that call your server are in [Test and CI](testing.md).

## Use it

```ts
import { NotesClient } from "./sdk/out/typescript-dist/esm/index.mjs";

const client = new NotesClient({ baseUrl: "http://localhost:5174" });
const note = await client.notes.create({ body: "first" });
for await (const n of await client.notes.list({ limit: 50 })) console.log(n.id, n.body);   // fetches the next page itself
```

```go
import (
	notes "github.com/you/billing-api/sdk/go"
	"github.com/you/billing-api/sdk/go/client"
	"github.com/you/billing-api/sdk/go/option"
)

c := client.NewClient(option.WithBaseURL("http://localhost:5174"))
note, err := c.Notes.Create(ctx, &notes.CreateInputBody{Body: "first"})
page, err := c.Notes.List(ctx, &notes.ListNotesRequest{Limit: notes.Int(50)})
for it := page.Iterator(); it.Next(ctx); {
	fmt.Println(it.Current().ID, it.Current().Body)
}
```

- **Without a base URL** the client calls the server the specs name: `API_URL`.
- **Streams:** [the client rule](streaming.md#the-client-rule).
- **The WebSocket** is `client.liveNotes.connect({ after })` in TypeScript (on Node it needs the `ws` package). The Go SDK has the message types only.
- **Each SDK has its own `README.md` and `reference.md`.**

These calls are the ones the tests make (`test/sdk-live-test.mjs`, `test/soak-go/main.go`) and the ones run on 2026-10-01 under the SDK's earlier names. The snippets as written were not run.

## The CLI

```sh
mise run sdk:cli:build     # HEAVY the first time: compiles every Rust dependency. -linux builds for Linux in Docker
sdk/out/cli/target/release/notes --base-url http://localhost:5174 notes list --page-all
```

- **Output and requests:** `--format json|table|yaml|csv|jsonl|raw|http`, `--query` (JMESPath), `--dry-run`, `--base-url`, `--debug`, `--schema`.
- **A stream prints in `json` and `jsonl` only when it ends.** `--format raw` prints as events arrive ([fern-api/fern#17939](../upstream.md)).
- **No command for the WebSocket channel.**
- **One binary per build:** for the machine you build on, or Linux with `-linux`.

## Add a language

Add a group to `fern/generators.yml`, under `groups:`.

```yaml
  python:
    generators:
      - name: fernapi/fern-python-sdk
        version: 5.34.0
        output:
          location: local-file-system
          path: ../sdk/out/python
```

```sh
mise run sdk:gen python     # -> sdk/out/python
```

- **A release then ships it** with no other change: every group but `cli` and those ending in `-dist` is archived.
- **`mise run sdk:check` builds and tests Go and TypeScript only.** For another language it says so.
- **What was tried:** the Python client was generated on 2026-10-01 and not used against a server. Fern's other generators (Java, C#, Ruby and more) take the same form; none was tried.

## Give the Go SDK to another repo

Go fetches a module from a git repository, and `sdk/out/` is not in yours. One task copies the Go SDK into a committed folder, `sdk/go/`, which is a module of its own: `<your module>/sdk/go`.

```sh
mise run spec           # after a contract change
mise run sdk:publish    # Docker: generates the Go SDK fresh, checks it, copies its sources into sdk/go
git add sdk/go          # commit it with the contract change it belongs to
```

In the other repo:

```sh
go get github.com/you/billing-api/sdk/go@main      # a branch or a commit, straight away
go get github.com/you/billing-api/sdk/go@latest    # a version, once a release has tagged it
```

| Task | What it does | Where it runs |
|---|---|---|
| `mise run sdk:publish:fresh` | Fails if the specs changed since `sdk/go/` was made from them. No Docker: it compares a hash | `mise run check` |
| `mise run sdk:publish:check` | Generates again and fails if `sdk/go/` differs, naming the files | The `sdk-check` workflow |

- **Never edit `sdk/go/`.** Its README starts with a "Generated code" banner.
- **Left out of the copy:** Fern's tests that need WireMock, `CONTRIBUTING.md`, and Fern's run record.
- **A private repo:** the machine that runs `go get` needs git access and `GOPRIVATE`.
- **Not handled:** major version 2 and later, where Go wants the module path to end in `/v2`. The TypeScript SDK has no committed copy and no package.

## Release

A release is a version tag. Push `vX.Y.Z` and the `release` workflow does the rest; on a pull request the same workflow is a dry run.

| Step | Task | What it makes |
|---|---|---|
| Archive the SDKs and specs | `mise run sdk:dist` | `dist/<project>-sdk-<group>.tar.gz` per SDK group, `dist/<project>-specs.tar.gz`. Generated fresh and checked first |
| Build the CLI | `mise run sdk:dist:cli` | `dist/<project>-cli-<os>-<arch>`; the workflow builds Linux on amd64 |
| Attach to the GitHub Release | `mise run release` | Every file in `dist/`. Without a tag: a dry run that lists them |
| Tag the Go SDK | `mise run release:tags` | `sdk/go/vX.Y.Z` on the tag's commit, so `@latest` and `@vX.Y.Z` work |

`<project>` is the project's folder name.

Not set up:

- **Packages.** Nothing publishes to npm or to a repository per SDK. Fern can (an `output:` with `location: npm`, or a `github:` block); not tried here.
- **The CLI for macOS and Windows.** Build it on the machine that needs it.
- **Fern's licence.** Fern's documentation describes local generation and the CLI generator as needing a `FERN_TOKEN`. Everything here ran without one; `mise run doctor` warns about it.
