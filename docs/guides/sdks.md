# Generate SDKs and a CLI

This page gets you a typed client for your API in Go and TypeScript, and a command-line program for it, generated by [Fern](https://buildwithfern.com) from the specs your contract writes. Read it when another developer, or another service of yours, has to call the API.

You need Docker running: Fern runs its generators in containers. Everything here was run on 2026-10-01 in a project made by `charter new -name billing-api -module github.com/acme/billing-api`, so the names below are that project's.

## Generate one

```sh
mise run spec                 # the specs, from the contract (do this after every contract change)
mise run sdk:gen typescript   # TypeScript source      -> sdk/out/typescript
mise run sdk:gen go           # a Go module            -> sdk/out/go
mise run sdk:gen typescript-dist   # TypeScript compiled to .js and .d.ts -> sdk/out/typescript-dist
mise run sdk:gen cli          # a Rust CLI, as source  -> sdk/out/cli
mise run sdk:list                    # the groups there are: "go typescript typescript-dist cli"
```

Each took 10 to 25 seconds here, with the generator images already downloaded. A generation replaces the folder.

- **`sdk/out/` is not committed** (it is in `.gitignore`). An SDK is a build output: generate it again from the committed specs. The one SDK that is committed is a copy of the Go one, in `sdk/go` ([Giving the Go SDK to another repo](#giving-the-go-sdk-to-another-repo)).
- **`typescript` or `typescript-dist`:** the first is `.ts` source, to copy into a TypeScript project or to read. The second is what Node or a Worker imports without a build step, and what the test programs in `test/` use.
- **`mise run sdk:ready`** generates the three groups the tests use (`typescript-dist`, `go`, `cli`) and builds the CLI, each only if its folder is missing. After a contract change, run `mise run sdk:clean` first, or generate the group again yourself: `sdk:ready` does not notice a stale SDK.

## What Fern reads: the Fern folder

```
fern/
├── openapi.json      written by mise run spec (never edit)
├── asyncapi.json     the same, for the WebSocket channel
└── generators.yml    yours: one group per SDK, with its options
```

A group in `fern/generators.yml` names a Fern generator, its pinned version, where the output goes, and its options. `fern/fern.config.json` holds the Fern organization name, and `package.json` pins Fern itself.

What an SDK contains comes from the contract, not from this folder: the method names (`notes.list`), auto-paging and the SSE stream are declared on each operation in `api/contract.go`.

## Check that an SDK works

```sh
mise run sdk:check sdk/out/go           # go build, go vet, and Fern's generated tests against a WireMock container
mise run sdk:check sdk/out/typescript   # a typecheck against standard fetch, without Node's types
mise run sdk:check-spec                 # Fern's own validation of the specs and generators.yml
```

Output here:

```
build ok
vet ok
tests ok
typecheck ok (sdk/out/typescript/index.ts)
```

`sdk:check` proves the SDK compiles and passes Fern's own tests against a mock. It does not call your server. The tests that do are in [Test locally and on Cloudflare](testing.md).

A `go` command typed inside `sdk/out/go` fails with `directory prefix . does not contain modules listed in go.work`: a folder git ignores cannot be in the workspace file. Put `GOWORK=off` in front of it (`GOWORK=off go test ./...`), which is what `sdk:check` does. The committed copy in `sdk/go` is in `go.work` and needs nothing.

## Build the CLI

```sh
mise run sdk:cli:build sdk/out/cli     # HEAVY the first time: compiles every Rust dependency
sdk/out/cli/target/release/billing-api --base-url http://localhost:5174 notes list --page-all
```

The build took 43 seconds here (an Apple M-series Mac). It needs Rust, which `mise install` provides at the version in `mise.toml`. With `-linux` before the folder it builds a Linux binary inside Docker instead, into `target-linux/`.

Run against `mise run run`:

```
$ billing-api --base-url http://localhost:5174 meta hello
{
  "message": "Hello from billing-api (go run)"
}
$ billing-api --base-url http://localhost:5174 notes create --body first
{
  "body": "first",
  "created_at": "2026-10-01 09:36:22",
  "id": 1
}
```

Without `--base-url` it calls the server named in the specs ([Deploy to Cloudflare](deploy.md#the-workers-url)). `--help` lists the rest: output formats (`--format json|table|yaml|csv|raw|jsonl|http`), `--query`, `--dry-run`, `--schema`.

Limits of the generated CLI:

- **`notes watch` prints nothing until the stream ends** in the `json` and `jsonl` formats. `--format raw` prints as events arrive, as raw SSE lines ([upstream issues](../upstream.md)).
- **No command for the WebSocket channel.**
- **One binary per build:** for the machine you build on, or Linux with `-linux`.

## Use the SDK

Both snippets were run against `mise run run`. Leave out the base URL and the client calls the server named in the specs.

TypeScript, importing the compiled SDK from the project's root:

```ts
import { BillingApiClient } from "./sdk/out/typescript-dist/esm/index.mjs";

const client = new BillingApiClient({ baseUrl: "http://localhost:5174" });

const note = await client.notes.create({ body: "first" });

// list: the SDK fetches the next page when the loop needs it
for await (const n of await client.notes.list({ limit: 50 })) console.log(n.id, n.body);

// watch: notes after a position, as they are created, until the stream ends
for await (const n of await client.notes.watch({ after: String(note.id - 1), seconds: 5 })) console.log("new", n.body);
```

Go:

```go
package main

import (
	"context"
	"errors"
	"fmt"
	"io"
	"log"

	billingapi "github.com/acme/billing-api/sdk/go"
	"github.com/acme/billing-api/sdk/go/client"
	"github.com/acme/billing-api/sdk/go/option"
)

func main() {
	ctx := context.Background()
	c := client.NewClient(option.WithBaseURL("http://localhost:5174"))

	note, err := c.Notes.Create(ctx, &billingapi.CreateInputBody{Body: "first"})
	if err != nil {
		log.Fatal(err)
	}

	// list: the iterator fetches the next page when it needs it
	page, err := c.Notes.List(ctx, &billingapi.ListNotesRequest{Limit: billingapi.Int(50)})
	if err != nil {
		log.Fatal(err)
	}
	for it := page.Iterator(); it.Next(ctx); {
		fmt.Println(it.Current().ID, it.Current().Body)
	}

	// watch: notes after a position, as they are created, until the stream ends
	after := fmt.Sprint(note.ID - 1)
	stream, err := c.Notes.Watch(ctx, &billingapi.WatchNotesRequest{After: &after, Seconds: billingapi.Int(5)})
	if err != nil {
		log.Fatal(err)
	}
	defer stream.Close()
	for {
		n, err := stream.Recv()
		if errors.Is(err, io.EOF) {
			return
		}
		if err != nil {
			log.Fatal(err)
		}
		fmt.Println("new", n.Body)
	}
}
```

A program inside the project points the SDK's module path at the generated folder. In that program's `go.mod`:

```
require github.com/acme/billing-api/sdk/go v0.0.0

replace github.com/acme/billing-api/sdk/go => ../sdk/out/go
```

A program in another repo needs no `replace` line: [Giving the Go SDK to another repo](#giving-the-go-sdk-to-another-repo).

- **A stream ends on purpose** after `seconds`. A client that wants to keep following calls `watch` again with `after` set to the last note id it received. The loop for each client is in [What a client does](../realtime.md#what-a-client-does).
- **The WebSocket** is `client.liveNotes.connect({ after })` in the TypeScript SDK (on Node it needs the `ws` package). The Go SDK has the message types only, no WebSocket client.
- **Each generated SDK has its own `README.md` and `reference.md`,** listing every method.

## Change the names

All of them are in `fern/generators.yml`. `charter new -name billing-api` set them from the project's name:

| Setting | Group | What it names | In a `billing-api` project |
|---|---|---|---|
| `config.module.path` | `go` | The Go module path of the SDK: the project's module (`-module`) with `/sdk/go` added | `github.com/acme/billing-api/sdk/go` |
| `config.packageName` | `go` | The Go package name | `billingapi` |
| `config.namespaceExport` | `typescript`, `typescript-dist` | The TypeScript client class, with `Client` added | `BillingApi` gives `BillingApiClient` |
| `config.binaryName` | `cli` | The CLI's binary | `billing-api` |

`module.path` must end in `/sdk/go`, the folder the SDK is committed to: that is how `go get` finds it, and `mise run sdk:publish` fails when it does not.

Then generate again. The test programs use these names, so change them there too: `BillingApiClient` in `test/sdk-live-test.mjs` and `test/soak.mjs`, the binary's name in `test/soak.mjs`, and the module path in `test/soak-go/main.go`, `test/soak-go/go.mod` and `test/soak.mjs`.

Method names (`client.notes.list`) are not here. They come from the contract: `x-fern-sdk-group-name` and `x-fern-sdk-method-name` on each operation in `api/contract.go`.

## Add a language

Add a group to `fern/generators.yml`, under `groups:`. For Python:

```yaml
  python:
    generators:
      - name: fernapi/fern-python-sdk
        version: 5.34.0
        output:
          location: local-file-system
          path: ../sdk/out/python
```

```sh
mise run sdk:gen python       # -> sdk/out/python
```

That ran here and produced the client. It was not used against a server, and `mise run sdk:check` knows only Go and TypeScript SDKs. Fern's other generators (Java, C#, Ruby and more) take the same form: the generator's name, a pinned version, and the options listed in Fern's documentation for that generator. None of those was tried.

## Giving the Go SDK to another repo

Go fetches a module from a git repository, and `sdk/out/` is not in yours. So one task copies the Go SDK into a folder that is committed, `sdk/go`. That folder is a Go module of its own, `github.com/acme/billing-api/sdk/go`, which another repo gets like any other.

In the project:

```sh
mise run spec      # after a contract change: the specs
mise run sdk:publish      # needs Docker: generates the Go SDK fresh, checks it as sdk:check does, copies its sources into sdk/go
git add sdk/go go.work    # then commit and push, with the contract change it belongs to
```

Output here:

```
build ok
vet ok
tests ok
published: sdk/go (module github.com/acme/billing-api/sdk/go, 47 files, 338 KB). Commit it; another repo gets it with: go get github.com/acme/billing-api/sdk/go@<branch, commit or version>
```

In the other repo, once that commit is on GitHub:

```sh
go get github.com/acme/billing-api/sdk/go@main      # the newest commit on main (a branch name or a commit hash)
go get github.com/acme/billing-api/sdk/go@latest    # the newest release, once the project has cut one
```

Then import it and call it as in [Use the SDK](#use-the-sdk), with no `replace` line.

- **What is in `sdk/go`:** the client's Go source, its `go.mod` and `go.sum`, Fern's `README.md` and `reference.md`, and the tests that run on their own. Left out: Fern's tests that need a WireMock container (`wiremock/` and the `*_test` folders), `CONTRIBUTING.md`, and Fern's record of the run (`.fern/`, which names the commit it ran at).
- **After a contract change, publish again.** `mise run check` fails until you do: `sdk:publish:fresh` sees that the specs are no longer the ones `sdk/go` was made from.
- **Never edit `sdk/go` by hand.** `mise run sdk:publish:check` generates the SDK again and fails when the folder differs, naming the files. The `sdk-check` workflow runs it on every push and pull request, so a contract change without `mise run sdk:publish` fails there. `mise run check` does not run it. Before the first publish there is no `sdk/go`, and the check passes.
- **A release gives it a version.** A Go module in a subfolder only has a version under a tag that starts with the folder. On a version tag `vX.Y.Z` the `release` workflow runs `mise run release:tags`, which adds `sdk/go/vX.Y.Z` on the same commit ([CI and releases on GitHub](ci-releases.md#cut-a-release)). After that `@latest` and `@vX.Y.Z` work.
- **`sdk/go` is in `go.work`:** `sdk:publish` adds it, so `go build` and `go test` work inside it.
- **A private repo:** the machine that runs `go get` needs git access to it, and `GOPRIVATE=github.com/acme/*` so that Go fetches it from GitHub and not through the public proxy.

Limits:

- **Only the Go SDK.** The TypeScript SDK has no committed copy and no package.
- **Major version 2 and later:** Go then wants the module path to end in `/v2`. Nothing here handles that.
- **What was run, on 2026-10-01:** `sdk-publish`, its check and the `release:tags` dry run, in a project made with `-from` a checkout, with the `charter` tool built from that checkout: the command is in releases of the tool made after that date. The Go program above built and ran from a module outside the project, against the project's `sdk/go`. `go get` from GitHub at a branch was run for charter's own `sdk/go`, not for a project's. No release has tagged an `sdk/go` yet.

## Hand the SDKs to others

Besides the Go module above, what exists is the release archive. A version tag on GitHub attaches these to the tag's GitHub Release ([CI and releases on GitHub](ci-releases.md#what-a-release-contains)):

| File | What is in it |
|---|---|
| `billing-api-sdk-go.tar.gz` | The Go SDK's source |
| `billing-api-sdk-typescript.tar.gz` | The TypeScript SDK's source |
| `billing-api-specs.tar.gz` | `openapi.json` and `asyncapi.json` |
| `billing-api-cli-linux-amd64` | The CLI, for Linux on amd64 |

To build the first three on your machine, without publishing anything:

```sh
mise run sdk:dist     # generates, checks and archives into dist/
```

Not set up:

- **Packages.** Nothing publishes the TypeScript SDK to npm or the Go SDK to a repository of its own. Fern can do both (an `output:` with `location: npm`, or a `github:` block, in place of `location: local-file-system`), and that has not been configured or tried here. A user of the TypeScript SDK copies the source into their project; a user of the Go SDK has the module in `sdk/go`.
- **The CLI for macOS and Windows.** Build it on the machine that needs it.
- **Fern's licence.** Fern's documentation describes local generation and the CLI generator as needing a `FERN_TOKEN`. Everything on this page ran without one; `mise run doctor` prints a warning about it.
