Contract-first APIs on Cloudflare Workers, with real-time (SSE + WebSockets) that doesn't lose data, and SDKs, a CLI and docs generated by Fern. One notes API is built twice as the reference: in TypeScript with oRPC (`examples/notes-ts/`) and in Go with Huma on workers-go (`examples/notes-go/`). You write the contract in code; the OpenAPI and AsyncAPI specs, the validation and the clients all come from it.

**Cost:** on Cloudflare a Go Worker costs about what the TypeScript one does: under 1 ms of CPU for a simple read, 1 to 2 ms with a database read, about 2 ms for a write. The first request in a new isolate costs about 10 ms ([details](docs/README.md#before-you-choose-go-what-it-costs-to-run)).

**All documentation is in [docs/](docs/README.md)**, rendered at https://joeblew999.github.io/charter/. Start with ["What is what"](docs/README.md#what-is-what).

## Quick start

Needs [mise](https://mise.jdx.dev) and Docker (for Fern).

```sh
mise install              # node, jq, gh, TinyGo (mise.toml), Go, Rust (each project's mise.toml)
mise run setup            # npm packages
mise run check            # every local check: both APIs, spec drift, SDKs, the SDK inside workerd
mise run dev          # the oRPC API on http://localhost:5173 (first time, in another shell: mise run migrate:local)
mise run dev       # the Go API on http://localhost:5174 (first time: mise run migrate:local)
mise run run       # the Go API natively, no Cloudflare (in-memory store)
mise tasks                # everything else: every task is one line
```

Deploying needs a Cloudflare login (`examples/notes-ts/node_modules/.bin/cf auth login`, or `CLOUDFLARE_API_TOKEN`):

```sh
mise run deploy       # the charter-notes-ts Worker, then its D1 migrations
mise run live-test    # SSE + WebSocket + the TypeScript SDK against it
mise run soak         # the real-time matrix (redeploys once mid-run)
mise run deploy    # the same three for the Go Worker (charter-notes-go)
mise run live-test
mise run soak
```

On another Cloudflare account, set `API_URL`, `API_URL` (and `API_URL`, `API_MOCK_URL`) in `mise.local.toml`, which is gitignored.

## Use it in another repo

Everything runs through one tool, straight from GitHub. Nothing to copy by hand.

```sh
charter() { go run github.com/joeblew999/charter/cmd/charter@latest "$@"; }

# A new Go API project (contract, Worker, tests, Fern folder, tasks, docs), under your name:
charter new -name billing-api && cd billing-api && git init
mise install && mise run setup && mise run check      # proves it works on your machine
mise run deploy && mise run live-test   # to Cloudflare, then test what was deployed

# In any repo that has a GitHub remote:
charter workflows -into .        # GitHub workflows (api-*, sdk-*), which only call mise tasks
charter docs -into .            # the docs site for docs/: config, writing rules, llms.txt
charter docs-lint               # check docs/: links, tasks and paths that don't exist
charter docs-review             # have Claude bring docs/ up to date against docs/writing.md
gh api -X POST 'repos/{owner}/{repo}/pages' -f 'source[branch]=main' -f 'source[path]=/docs'   # once: turn the site on
```

The first line `charter new` prints is the tool's version and what it pinned to it (the tool in `mise.toml`, the Go packages in `examples/notes-go/go.mod`): minutes after a release `@latest` can still be the previous one, while the release binary or `charter@vX.Y.Z` is exact.

Or make the tool a mise tool of your project, so its tasks can call `charter <command>` and the version is pinned in one place:

```toml
[tools]
"go:github.com/joeblew999/charter/cmd/charter" = "latest"                                   # built with Go
# or a prebuilt binary, no Go needed:
"ubi:joeblew999/charter" = { version = "latest", exe = "dev", matching = "dev_" }
```

A project made by `new` has that tool line and all of these as one-line tasks already (`mise tasks`). What each command does: [docs/dev.md](docs/dev.md). For an agent: start at [AGENTS.md](AGENTS.md), or https://joeblew999.github.io/charter/llms.txt.
