[![api-check](https://github.com/joeblew999/orpc-api/actions/workflows/api-check.yml/badge.svg)](https://github.com/joeblew999/orpc-api/actions/workflows/api-check.yml)

[![latest release](https://img.shields.io/github/v/release/joeblew999/orpc-api)](https://github.com/joeblew999/orpc-api/releases/latest)

Contract-first APIs on Cloudflare Workers, with real-time (SSE + WebSockets) that doesn't lose data, and SDKs, a CLI and docs generated by Fern. One notes API is built twice as the reference: in TypeScript with oRPC (`api/`) and in Go with Huma on workers-go (`api-go/`). You write the contract in code; the OpenAPI and AsyncAPI specs, the validation and the clients all come from it.

**Cost, before you choose Go:** on Cloudflare a read costs 1 to 3 ms of CPU with the Go Worker and a write about 4 ms, close to the TypeScript one (about 1 ms). The first request a new isolate serves costs 40 to 100 ms ([details](docs/README.md#before-you-choose-go-what-it-costs-to-run)).

**All documentation is in [docs/](docs/README.md)**, rendered at https://joeblew999.github.io/orpc-api/. Start with ["What is what"](docs/README.md#what-is-what).

## Quick start

Needs [mise](https://mise.jdx.dev) and Docker (for Fern).

```sh
mise install              # node, jq, gh, TinyGo (mise.toml), Rust (rust-toolchain.toml), Go (go.work)
mise run setup            # npm packages
mise run check            # every local check: both APIs, spec drift, SDKs, the SDK inside workerd
mise run api:dev          # the oRPC API on http://localhost:5173 (first time, in another shell: mise run api:migrate:local)
mise run api-go:dev       # the Go API on http://localhost:5174 (first time: mise run api-go:migrate:local)
mise run api-go:run       # the Go API natively, no Cloudflare (in-memory store)
mise tasks                # everything else: every task is one line
```

Deploying needs a Cloudflare login (`api/node_modules/.bin/cf auth login`, or `CLOUDFLARE_API_TOKEN`):

```sh
mise run api:deploy       # the orpc-api Worker, then its D1 migrations
mise run api:live-test    # SSE + WebSocket + the TypeScript SDK against it
mise run api:soak         # the real-time matrix (redeploys once mid-run)
mise run api-go:deploy    # the same three for the Go Worker (orpc-api-go)
mise run api-go:live-test
mise run api-go:soak
```

On another Cloudflare account, set `API_URL`, `API_GO_URL` (and `HARNESS_URL`, `HARNESS_API_URL`) in `mise.local.toml`, which is gitignored.

## Use it in another repo

Everything runs through one tool, straight from GitHub. Nothing to copy by hand.

```sh
dev() { go run github.com/joeblew999/orpc-api/dev@latest "$@"; }

# A new Go API project (contract, Worker, tests, Fern folder, tasks, docs), under your name:
dev new -name billing-api && cd billing-api && git init
mise install && mise run setup && mise run check      # proves it works on your machine
mise run api-go:deploy && mise run api-go:live-test   # to Cloudflare, then test what was deployed

# In any repo that has a GitHub remote:
dev workflows -into .        # GitHub workflows (api-*, sdk-*), which only call mise tasks
dev docs -into .            # the docs site for docs/: config, writing rules, llms.txt
dev docs-lint               # check docs/: links, tasks and paths that don't exist
dev docs-review             # have Claude bring docs/ up to date against docs/writing.md
gh api -X POST 'repos/{owner}/{repo}/pages' -f 'source[branch]=main' -f 'source[path]=/docs'   # once: turn the site on
```

The first line `dev new` prints is the tool's version and what it pinned to it (the tool in `mise.toml`, the Go packages in `api-go/go.mod`): minutes after a release `@latest` can still be the previous one, while the release binary or `dev@vX.Y.Z` is exact.

Or make the tool a mise tool of your project, so its tasks can call `dev <command>` and the version is pinned in one place:

```toml
[tools]
"go:github.com/joeblew999/orpc-api/dev" = "latest"                                   # built with Go
# or a prebuilt binary, no Go needed:
"ubi:joeblew999/orpc-api" = { version = "latest", exe = "dev", matching = "dev_" }
```

A project made by `new` has that tool line and all of these as one-line tasks already (`mise tasks`). What each command does: [docs/dev.md](docs/dev.md). For an agent: start at [AGENTS.md](AGENTS.md), or https://joeblew999.github.io/orpc-api/llms.txt.
